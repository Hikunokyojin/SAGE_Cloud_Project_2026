# Loophole register

Small gaps found while testing each stage. "Covered by" names the later task that fixes it;
**none** means no planned task fixes it, so it needs a decision.

| # | Found in | Loophole | Evidence | Covered by |
|---|----------|----------|----------|------------|
| L1 | T3.4 live test | Flat-plan prices ignore volume. Brevo ($7.50) and SendGrid ($19.95) are plan prices that likely do not cover 100k emails, yet they beat per-email services. | rt-live request: Brevo chosen at $7.50 for "about 100k emails a month" | **Fixed (T4.1b)**: catalogue v2.1.0 records each flat plan's quota; the Negotiator rejects a plan whose quota is below the stated volume (naming both numbers) and notes unmetered or unconfirmed plans |
| L2 | T3.4 | Per-unit budgets ("under $0.05 per image") are compared with monthly prices, so they match almost nothing. Intent still emits raw dollar limits. | Design decision in T3.4; Intent unchanged to keep the offline T01-T08 set valid | **T4.1a (done)**: Intent marks per-unit price limits and converts them to monthly limits when the request states a volume. Without a volume the per-unit flag remains. **Fixed (T4.1b)**: the Negotiator checks such a limit against each service's price per unit; a flat plan with no quota is rejected as having no per-unit price |
| L3 | T3.4 | The monthly estimate uses a fixed usage profile (100k requests, 100k emails...), not the volume the user states. | Request said 100k emails; matched the default by coincidence | **T4.1a (done)**: Intent extracts the stated monthly volume per request or per step. **Fixed (T4.1b)**: the Conductor passes the volume on and the Negotiator re-prices metered services at it (services priced in other units keep the standard estimate, with a note) |
| L4 | T3.4 calibration | Out-of-catalogue refusal fell to 60% on v2 (target at least 95%). Near neighbours: Kubernetes 0.546, e-signatures 0.520. | results/retrieval-calibration-v2.json | Measured by T4.2 / RT15 in T5.2, **fix: none** |

RT6 passed only with a simulated outage written straight to MongoDB. | scripts/simulate-outage.ts used for RT6 | **Fixed in WP3.5**: the probe workflow upserts the live catalogue after each run (needs the `MONGO_URI` repository secret, and the schedule needs the workflow on `main`) |

| L10 | WP3.5 testing | Each CDK stack test run left ~24 `cdk.out*` folders (~200 MB each) in %TEMP%; 566 of them filled the disk to 0 MB. | 115 GB found 2026-11-12 | **Fixed in WP3.5**: the tests synthesise into one folder that is deleted afterwards |
| L11 | WP3.5 deploy | The sharp Linux binaries the Broker bundle needs are installed with `--no-save`, so any later `npm install` removes them and the next broker build fails half-way (`dist/index.js` written, native modules not copied). The stale-bundle guard (L7) does not catch a half-finished build. | Broker build failed after the WP3.5 `npm install` | **Fixed in WP4 (L11)**: the broker build fetches the pinned binaries itself with `npm pack` when missing, and a failed build deletes `dist/index.js` and `dist/node_modules` so no half-built bundle can be deployed |
| L12 | T4.1b | The Reviewer checks the price the Negotiator wrote on the chosen service. | L13 | T4.1b | A quota in a different unit from the request (for example a plan counted in requests for a request stated in emails) cannot be checked; the plan is kept with a note. | Code review of T4.1b | No fix planned; the note is shown in the explanation (T4.1e) |

| L16 | T4.1d live test | A translation step stated in pages could not price a per-character service, so it kept the standard 1M-character estimate whatever the real amount. | live-t41d-1: AWS Translate $15 for 5,000 pages | **Fixed (T4.1 units)**: pages convert to characters at an assumed 2,000 characters a page, and the note states the assumption.
